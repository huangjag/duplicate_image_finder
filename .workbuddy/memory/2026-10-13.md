## duplicate_image_finder_v2.py — 新增菜单选项 [8] 删除重复文件

- 需求：依据扫描结果删除重复文件（每组只保留 1 个），保留优先级：①体积最大 → ②修改日期最新（只看日期）→ ③同日期文件名（字典序，忽略大小写）最大。进入时先显示数据库对应扫描目录；库空则提示先扫描并返回主菜单。
- 用户决策：删除范围「运行时让我选」；删除方式「移入系统回收站（可恢复）」；「直接删无需确认」（靠回收站可恢复 + 删除前打印审计摘要兜底）；「文件名最大」= 字典序最大、忽略大小写。
- 实现（全部为新增，未改动既有逻辑）：
  - `_recycle_key(row)`：`(size, (y,m,d), name.lower())` 降序取 max 即保留项。
  - `move_to_trash(paths)`：降级顺序 `send2trash`（软依赖）→ Windows `shell32.SHFileOperationW`(FOF_ALLOWUNDO) → `os.remove`。返回 (deleted, failed, skipped)。
  - `_iter_delete_groups(conn, mode)`：mode = exact/visual/both，产出含 mtime 的组；不改动 `iter_exact_groups`/`iter_visual_groups`（避免影响 export）。
  - `delete_duplicates(conn, db_path)`：显示 DB 路径与 root；空库直接返回；交互选类别；用 `scheduled` 集合去重（both 模式同一文件不被两组重复处理）；打印计划摘要后直接删除；同步 `files` 表（DELETE by path，BATCH 分批）。
  - `menu()` 新增 [8] 文本与分支（沿用选项 [3] 的 open/close 模式 + continue）。
- 关键坑：**SHFileOperationW 返回值不可靠**——沙箱里返回 2（非 0）但文件实际已被删除，导致误报失败且不清理 DB。改为**以 `os.path.exists` 事后判定成功**（deleted = 文件已不存在），不再依赖返回码，也不再逐文件重试。
- 测试：托管 Python 未装 numpy/PIL，用桩模块（sys.modules 注入假 numpy / PIL.Image）跑纯逻辑测试，4 个用例全通过：内容重复 keep=img_003.jpg（同日取名字最大）；视觉相似 keep=v_b.jpg（体积最大优先）；空库分支返回；端到端删除后 DB 计数 5→3。
